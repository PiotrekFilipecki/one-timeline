Sequence, then overlap

The same jump, eight times. Only the third argument of .to() changes, and the stiff queue turns into one movement.

Ease is spacing

Twelve frames of one move. Time ticks evenly; the ease decides where each frame lands. Dense means slow, sparse means fast.

One tween, a whole grid

Stagger reads the grid, not the DOM order. One tween, one ScrollTrigger, 112 letters.

What a frame costs

Every glyph on transform. Style, then straight to the GPU compositor. No layout, no paint.

Now the same glyphs on left and top, reading offsetLeft after every write. Layout runs once per element, and you can feel it.

Back on transform. 16.7 ms per frame at 60 Hz, 8.3 ms at 120 Hz, and GSAP runs on the main thread, so keep it free.

Reverse is its own shot

Reversing expo.out plays it backwards, so the exit crawls like expo.in. With easeReverse (GSAP 3.15) the exit keeps its own curve.

Engineering notes

    

      
Beats are functions
Each beat builds and returns a timeline. The master only holds labels and relative positions, so lengthening one beat moves everything after it. No delay for sequencing, ever.

      
Transform and opacity
They skip layout and paint and go straight to the compositor. left, top, width re-run layout every frame. clip-path and colour repaint.

      
Layers cost memory
force3D: "auto" promotes only while tweening. A layer is width × height × DPR² × 4 bytes.
 ×  @ x = 31.6 MB

      
The main thread
GSAP ticks on requestAnimationFrame. A busy main thread (hydration, JSON, analytics) freezes it while CSS transform animations keep running. lagSmoothing(500, 33) hides the jump; use lagSmoothing(0) or drive the timeline from audio.currentTime when syncing to sound.

      
React without the cost
useGSAP with a scope, timelines in useRef, handlers in contextSafe. Never setState inside onUpdate: write to the DOM through a ref. Strict Mode double-mounts; the revert handles it.

      
Measure, don't guess
DevTools Performance with 4–6× CPU throttling, Paint flashing and Layer borders, then a real mid-range Android. The Long Animation Frames API reports frames over 50 ms with script attribution (Chrome and Edge 123+).
